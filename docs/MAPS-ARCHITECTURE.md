# Help Me ช่วยด้วย: สถาปัตยกรรมแผนที่และการค้นหาที่อยู่

## เป้าหมาย
- ฟรี 100% ไม่มีค่า API และไม่ต้องผูกบัตร (ไม่มี billing)
- ไม่ใช้ Google Maps, Google Places หรือ Mapbox แบบเสียเงิน
- ใช้ข้อมูล OpenStreetMap (OSM) แสดงถนนและซอยในไทยให้ละเอียดที่สุดเท่าที่ OSM มี
- ใช้ง่ายบนมือถือ: ปักหมุดด้วย GPS แล้วลากหรือแตะเพื่อแก้ตำแหน่งเองได้
- รองรับผู้ใช้จำนวนมาก โดยไม่ทำให้ UX ซับซ้อน

## ส่วนประกอบ (เวอร์ชัน 172 ขึ้นไป)

| หน้าที่ | ใช้อะไร | ค่าใช้จ่าย / เงื่อนไข |
|---|---|---|
| แผนที่ปักหมุดในฟอร์ม | MapLibre GL JS 5.24 (`pickmap.js`) | open source (BSD) |
| ข้อมูลแผนที่ | OpenFreeMap (vector tiles จาก OSM, style `liberty` / `dark`) | ฟรี ไม่มีลิมิต ไม่ต้องใช้ key ใช้เชิงพาณิชย์ได้ ต้องใส่เครดิต |
| แผนที่หน้าแรก / รายการเคส / รายละเอียดเคส | Leaflet + พื้นแผนที่ OpenFreeMap (ผ่าน maplibre-gl-leaflet) | เหมือนข้างบน |
| ตำแหน่ง GPS | Browser Geolocation API (`watchPosition`, เก็บค่าที่แม่นที่สุด) | ฟรี |
| ค้นหาที่อยู่ / พิกัดเป็นที่อยู่ | Photon ผ่าน proxy ของเรา `/api/geo/*` | public Photon ใช้ได้แบบ fair use (ดูด้านล่าง) |
| บอกซอย | คำนวณในเครื่องผู้ใช้จากเส้นถนนใน vector tiles (`nearestRoads`) + แขวง/เขตจาก Photon reverse | ไม่เรียก API เพิ่ม |
| ภาพดาวเทียม (ตัวเลือกเสริม) | Esri World Imagery | ไม่ใช่ส่วนหลัก ปิดได้ทันที |

เครื่องที่ไม่รองรับ WebGL จะใช้ Leaflet และแผนที่ภาพ (raster) อัตโนมัติ: ปักหมุดได้ปกติ แต่หาซอยได้หยาบกว่า (ใช้ Photon แทน)

## วิธีหาซอยให้แม่น
1. เมื่อหมุดถูกวาง (GPS, แตะ, ลาก หรือวางลิงก์) แผนที่จะซูมอย่างน้อยระดับ 16 แล้วรอให้ tile รอบหมุดโหลดเสร็จ
2. อ่านเส้นถนนที่มีชื่อจาก source layer `transportation_name` (ชื่อไทยจาก `name:th` หรือ `name`)
3. วัดระยะจากหมุดถึงเส้นถนนจริงทุกเส้น (point-to-segment) แล้วเรียงจากใกล้สุด ไม่นับทางเดินและราง
4. แสดงซอยไม่เกิน 4 ตัวเลือกพร้อมระยะเป็นเมตร ตัวแรกถูกเติมลงที่อยู่ ผู้ใช้แตะเปลี่ยนได้
5. ถามแขวงและเขตจาก Photon reverse แล้วประกอบเป็น "ซอย… แขวง… เขต… กรุงเทพฯ"

ความแม่นยำขึ้นกับหมุดเป็นหลัก ระบบจึงแสดงวงความแม่นยำของ GPS และเตือนให้ลากหมุดเมื่อ GPS คลาดเกิน 40 ม.

## Proxy ค้นหาที่อยู่ `/api/geo` (Cloudflare Pages Function)
ไฟล์: `functions/api/geo/[[path]].js`

- `GET /api/geo/api?q=…` ค้นหาสถานที่ (ส่งต่อไป Photon `/api/`)
- `GET /api/geo/reverse?lat=…&lon=…` แปลงพิกัดเป็นที่อยู่ (ส่งต่อไป Photon `/reverse`)
- ส่งต่อเฉพาะพารามิเตอร์ที่ Photon ใช้ ยุบช่องว่างในคำค้น และปัดพิกัดเหลือประมาณ 1 ม. เพื่อให้แคชได้ผล
- แคชที่ขอบเครือข่าย Cloudflare: ผลค้นหา 1 วัน, ผล reverse 7 วัน
- ลำดับเซิร์ฟเวอร์: `PHOTON_URL` (ถ้าตั้งไว้) แล้วค่อย `photon.komoot.io` ถ้าเซิร์ฟเวอร์แรกล่มหรือช้าเกิน 4 วินาที ระบบลองตัวถัดไปเอง
- ฝั่งแอป (`geocode.js`) เรียกผ่าน proxy ก่อน ถ้า proxy ใช้ไม่ได้จึงเรียก Photon สาธารณะตรง

## เมื่อไหร่ควรตั้ง Photon เอง (self-hosted)
public Photon (`photon.komoot.io`) ใช้ได้ "ในปริมาณที่สมเหตุสมผล" เท่านั้น ถ้าใช้หนักจะถูกจำกัดหรือแบน และไม่มีการรับประกันว่าจะใช้ได้ตลอด แคชที่ proxy ช่วยลดจำนวนครั้งที่เรียกได้มาก แต่ถ้าผู้ใช้หลักหมื่นคนต่อวัน หรือ public ช้าหรือล่ม ให้ตั้ง Photon เอง

### สเปกเครื่องสำหรับข้อมูลประเทศไทย
- VPS ราคาประหยัด 2 vCPU / RAM 4 GB / SSD 20–30 GB ก็พอ (ข้อมูลทั้งโลกต้องใช้ RAM 64 GB และดิสก์ 95 GB แต่ข้อมูลไทยประเทศเดียวเล็กกว่ามาก)
- Java 21 ขึ้นไป และ Photon เวอร์ชันล่าสุด

### ขั้นตอน
1. ดาวน์โหลดฐานข้อมูลไทยที่สร้างไว้แล้วจาก GraphHopper: `https://download1.graphhopper.com/public/` (จัดตามทวีป ดูโฟลเดอร์ `asia/thailand/`, ไฟล์ `photon-db-*.tar.bz2`)
   - ถ้าไม่มีไฟล์ db สำหรับไทย ให้ใช้ไฟล์ `photon-dump-*.jsonl.zst` แล้ว import ตามคู่มือ Photon หรือสร้างเองจาก Nominatim
   - ใช้เวอร์ชันของฐานข้อมูลให้ตรงกับเวอร์ชัน Photon (Photon 0.7.3 ขึ้นไปจะไม่ยอมเปิดถ้าใช้ไฟล์ผิดเวอร์ชัน)
2. แตกไฟล์แล้วรัน `java -jar photon-*.jar serve` (ค่าเริ่มต้นฟังที่พอร์ต 2322)
3. วาง reverse proxy (Caddy หรือ Nginx) พร้อม HTTPS ไว้ด้านหน้า หรือใช้ Cloudflare Tunnel เพื่อไม่ต้องเปิดพอร์ต
4. ใน Cloudflare Pages ของโปรเจกต์ helpme-th ไปที่ **Settings › Environment variables** แล้วเพิ่ม `PHOTON_URL = https://photon.example.org` จากนั้น redeploy
   - ไม่ต้องแก้แอปหรือรอให้มือถือผู้ใช้อัปเดต
   - ถ้าเครื่องเราล่ม proxy จะกลับไปใช้ public Photon เอง
5. อัปเดตข้อมูลรายสัปดาห์: ดาวน์โหลดไฟล์ใหม่ไปไว้อีกโฟลเดอร์ แตกไฟล์ สลับโฟลเดอร์ รีสตาร์ต แล้วลบของเก่า (ห้ามแตกไฟล์ทับของเดิม ข้อมูลจะเสีย)

## แผนที่ (tiles) เมื่อผู้ใช้เยอะมาก
- OpenFreeMap สาธารณะไม่มีลิมิต แต่อยู่ได้ด้วยเงินบริจาค ถ้าโหลดหนักมาก ควรพิจารณาบริจาคหรือตั้งเอง
- ทางเลือกตั้งเองแบบไม่มีเซิร์ฟเวอร์: ทำไฟล์ PMTiles เฉพาะประเทศไทยด้วย Planetiler หรือ Protomaps แล้วฝากไว้ที่ Cloudflare R2 ซึ่งมี free tier และไม่คิดค่า egress จากนั้นเปลี่ยน URL ของ source ใน style
- service worker เก็บ tile ที่ผู้ใช้เคยเห็นไว้แล้ว (ไม่เกิน 1,500 ไฟล์) ไฟล์ `.pbf` เปลี่ยนไม่ได้ จึงไม่ต้องโหลดซ้ำ ช่วยลดภาระเซิร์ฟเวอร์ และยังเห็นแผนที่ได้ตอนเน็ตอ่อน
